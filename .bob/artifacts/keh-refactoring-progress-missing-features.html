Missing features — UI & interactions (Phase 3b)

These are gaps in the current pages compared to the prototype. No backend required — all are frontend/UX work.

Campaign wizard — state does not persist to content library

Completing the wizard (Schedule / Publish Now / Save Draft) currently does nothing. The post does not appear in /content or /calendar. The prototype added the post to state.posts in-memory. Needs a shared client-side store (React context or Zustand) so wizard output lands in the content and calendar pages for the session.

Product modal — Add / Edit product

The "Add product" and "Edit product" buttons on /products do nothing. The prototype had a dialog with name, price, description, category, availability, promo price, product link, photo upload, and AI notes fields. Needs a modal component backed by local state.

Calendar — post detail modal + drag-to-reschedule

Clicking a calendar post chip does nothing. The prototype opened a modal with reschedule form and reuse/analytics actions. Drag-and-drop rescheduling is also absent.

Content library — Reuse / Duplicate / Edit actions

The three action buttons on each content card are rendered but wired to nothing. "Reuse" should pre-fill the campaign wizard. "Duplicate" should create a draft copy. "Edit" should open the wizard at the content step for non-published posts.

Dashboard recommendation — "Why this recommendation?" modal

The button is rendered but opens nothing. Should show a dialog with confidence source, data reasoning, and sample post history.

TopBar — Notifications panel

The bell icon is rendered but does nothing. Prototype showed a dropdown with "TikTok needs your finishing touch" and "Your weekly recommendation is ready" notifications.

Brand profile — save actually updates data

The save button shows a "✓ Saved" flash but does not propagate changes. Business name in the sidebar and AI captions should reflect saved brand profile values.

Social accounts — disconnect confirmation dialog

Disconnect immediately fires. Prototype showed a confirmation modal first ("Your prepared content stays in the library…").

Subscription — upgrade and manage plan modals

Both buttons are rendered but open nothing. Should show a plan preview dialog (Growth plan details) and a current billing summary modal respectively.

Analytics — performance table images + format column

The performance table shows title, platform, status, and reach but omits the product thumbnail and "Format / Tone / Price shown / Time" columns visible in the prototype.

Settings — "fresh mode" actually empties dashboard data

The toggle is wired to local state but does not affect /dashboard, /analytics, or /assistant. Those pages should detect the setting and show the empty-state cold-start experience instead of sample data.

Campaign wizard — Regenerate caption actually varies output

Hitting "Regenerate" calls generateCaptions(variation=true) which changes the opening line but uses the same template. In a real implementation this calls the AI service. A more varied template mock would improve the demo experience.

Calendar — week view

The "Week" toggle is rendered and switches the state variable but renders the same month grid. Prototype showed a 7-day horizontal layout for the current week.

Post status badge — "Active" vs "Inactive" on products

Product cards currently reuse PostStatusBadge with PUBLISHED / FAILED as a workaround. Should have a dedicated AvailabilityBadge component with correct "Active" / "Unavailable" labels.

Assistant page — "Apply to future posts" preference is local only

The price-first toggle on the assistant page does not cross-communicate with the campaign wizard or settings page. In the prototype it was global state.

Missing features — architecture (Phase 4)

Global client-side session store

The prototype used a single mutable state object. The refactored app has no equivalent shared store. Adding/editing products or completing the campaign wizard does not propagate across pages. Phase 4 should introduce a lightweight React context (or Zustand) for session-level state: products, posts, brand preferences.

Pages still import mock data directly

Several pages (/dashboard, /content, /calendar, etc.) import from src/data/ directly rather than calling src/services/. The service layer exists but is not used by the UI yet. Phase 4 should route all data access through service functions so the Supabase swap is a one-file change per entity.

Shared campaign state across routes

CampaignContext is mounted only inside /campaigns/new. A broader context or store is needed to pass the "Reuse campaign" pre-fill from the content library into the wizard, and to persist wizard output into the calendar and content list.
